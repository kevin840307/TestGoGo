# 掛機監控模式 / AFK Monitor (2026-11-08)

## UI 操作

- 遊戲右上方新增「掛機」，沿用現有頂部操作的樣式與 `show_message_box(type=2)` 確認／取消模式。
- 確定後在同一個遊戲視窗顯示單一監控面板，每秒更新連線狀態、待命／移動／打怪／死亡／換圖、HP／MP、角色、地圖座標、掛機時間、卸載貼圖數量。
- 監控模式的「返回遊戲」也要再次確認。載入中與換圖中暫時不允許返回，避免重入或載入中途恢復。
- 不新增第二個程式，也不影響玩家原先依帳號保存的 FPS 和畫質設定。

## 第一階段：保留遊戲執行、關閉完整遊戲畫面

- `GameManager.begin_afk_mode()` 保留 Player / Map / NetworkEntityManager / NetworkManager、碰撞、NPC、怪物、地面道具與網路狀態，隱藏 2D 世界及大部分 HUD，監控介面保持 20 FPS。
- 物理邏輯與收包維持固定 physics tick。NetworkEntityManager 在 AFK 切到 `_physics_process` 執行與普通 `_process` 相同的邏輯，避免生怪佇列隨 20 FPS 變慢。
- 掛機模式鎖定滑鼠自動行走目的地，避免滑鼠移到監控 UI 讓角色突然改道；返回後恢復一般輸入。
- 不會修改 Server 或中斷 WebSocket。這是本機畫面效能模式，並非自動開始打怪的外掛。

## 第二階段：卸載可恢復的視覺資源

- 掛機啟用 MultiBox + Mass（關閉戰鬥光效並簡化其他角色、怪物），並清理 Doll/Monster/Effect/Pet 的未引用快取。
- `AfkVisualCache` 逐一釋放靜態地圖 Sprite2D / TextureRect / Polygon2D / NinePatchRect 的 **可透過 res:// 路徑安全還原**貼圖，紀錄的只有資源路徑與 Node WeakRef，不保留資源強引用。
- **不**卸載 CollisionObject2D 子樹、`Entities`、CharacterBody2D、TileMapLayer、AnimatedSprite2D 和已掛腳本的地圖節點。這些可能影響移動、打怪、拾取、動畫訊號與座標。
- 返回時每批最多重新載入 24 張貼圖，恢復玩家原本畫質與視覺簡化偏好，再恢復地圖顯示；必要時依最新 Server packets 繼續同步。
- 掛機中伺服器要求換圖：正常執行換圖與位置同步，新的地圖在完成重建後再次卸載靜態畫面，避免套用舊地圖的資源快照。
- 不保證所有地圖的 RAM/VRAM 會等比例下降：不可安全重建的子資源或被其他系統引用的貼圖會保留。實際改善應觀察 **[AFK_MODE]** 的數值與 Windows process RAM/GPU 工作集，不能只用 `released` 數量推估。

## 測試及限制

- CI 靜態契約：`python -m unittest tests/test_afk_mode_contract.py`。
- Godot 行為測試：`godot --headless --path client --script res://tests/afk_visual_cache_regression.gd`。驗證靜態資源確實可卸載還原、玩家與地面物件未被刪、隱藏場景依然執行物理回呼。
- 尚需 Windows 遊戲實測：開啟自動打怪與自動拾取，掛機前／中／後與掛機中換圖各跑一段時間，比對 Server 擊殺、物品數量與 [PHYSICS_CADENCE]、[AFK_MODE]。
- 由於目前地圖/遊戲邏輯並未完全拆成獨立的 Server-driven headless world model，**不採用直接刪除整張地圖或活體 Entity 的做法**；這類全面重構必須再建立相應的自動戰鬥、碰撞與拾取 E2E 測試，不能冒充已完成。

- 對於可由 `res://` 還原、且未連接遊戲事件的 AnimatedSprite2D 與舊版 AnimatedMapObject，亦可卸載 SpriteFrames 並於恢復時還原原動畫、frame、播放狀態。
- 貼圖重新載入失敗不會顯示殘缺世界：失敗資源留在 retry 清單，返回按鈕可再次嘗試；已消失的舊地圖視覺節點自動跳過。
