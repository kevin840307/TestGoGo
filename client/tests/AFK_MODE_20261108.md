## 2026-11-08 — Original AFK monitor restoration progress

The existing GameHUD AFK monitor, including its custom mouse cursor, labels,
confirmation and return button, remains intact. A hidden SmoothLoadingBar is
shown only after pressing its original Return to Game button. Actual scene
threaded-load progress drives 8–65%; map instance/attach/buildings account for
68–85%; still-live player/remote Entity visual references are restored in
small groups of four or with a ~6 ms budget each frame (86–98%); 100% is only
sent after the world is visible and existing gameplay objects remain intact.
The final progress animation plays before the original monitor is hidden.

There is no new AFK UI, login preload change, WorldReady resend, packet
throttling, AI pause, physics-rate modification, or Server AOI change.

- Legacy maps without a dedicated `Entities` node no longer preserve the
  whole `ObjectContainer`. AFK creates a fresh lightweight `Entities`
  container and moves only the local player plus currently active
  NetworkEntityManager entities. Static decorations in `ObjectContainer`
  are therefore actually freed.

## 2026-11-08 — AFK true low-memory render shell

AFK is now a **client-presentation-only** memory mode. It does not change
server AOI, packet subscriptions, packet cadence, WebSocket/TCP behavior,
WorldReady semantics, fixed physics, movement, combat, pickup logic, timers,
or authoritative entity objects.

When AFK starts:
- the live `Entities` subtree is reparented intact into a tiny hidden shell;
- the entire static map scene is immediately `free()`d (not merely hidden);
- local/remote player paper dolls and monster SpriteFrames/effect references
  are released while their CharacterBody/collision/state nodes stay alive;
- visual loader caches, item/skill icons, silent audio cache, festival
  textures, paper-doll generated frame cache and hidden lazy UI preloads are
  cleared;
- any new entity arriving from normal network traffic is still created and
  tracked normally, but its optional artwork is immediately suspended.

On return, the current map PackedScene is loaded again while the AFK dashboard
stays active. The same preserved `Entities` subtree is reparented into the
new visual map. No entity is re-requested or respawned from the server.
User-selected performance/simplification settings are then restored and
visuals rebuild from current client state.

This intentionally trades some AFK-exit visual reload time for a much lower
resident footprint. The ~200 MB pre-world Godot/UI/script baseline is not
expected to disappear; the goal is to remove most memory added by entering a
large map.

# 掛機監控模式 / AFK Monitor (2026-11-08)

## UI 操作

- 遊戲右上方新增「掛機」，沿用現有頂部操作的樣式與 `show_message_box(type=2)` 確認／取消模式。
- 確定後在同一個遊戲視窗顯示單一監控面板，每秒更新連線狀態、待命／移動／打怪／死亡／換圖、HP／MP、角色、地圖座標、掛機時間、卸載貼圖數量。
- 監控模式的「返回遊戲」也要再次確認。載入中與換圖中暫時不允許返回，避免重入或載入中途恢復。
- 不新增第二個程式，也不影響玩家原先依帳號保存的 FPS 和畫質設定。

## 第一階段：保留遊戲執行、關閉完整遊戲畫面

- `GameManager.begin_afk_mode()` 保留 Player / Map / NetworkEntityManager / NetworkManager、碰撞、NPC、怪物、地面道具與網路狀態，隱藏 2D 世界及大部分 HUD。**監控介面有焦點時上限 20 FPS，失焦時停止 RenderingServer 渲染迴圈，且暫停監控文字計時器與小地圖；重新聚焦再恢復監控更新。**
- 物理邏輯與收包維持固定 physics tick。NetworkEntityManager 在 AFK 切到 `_physics_process` 執行與普通 `_process` 相同的邏輯，避免生怪佇列隨 20 FPS 變慢。
- 掛機模式鎖定滑鼠自動行走目的地，避免滑鼠移到監控 UI 讓角色突然改道；返回後恢復一般輸入。
- 不會修改 Server 或中斷 WebSocket。這是本機畫面效能模式，並非自動開始打怪的外掛。

## 第二階段：卸載可恢復的視覺資源

- 掛機啟用 MultiBox + Mass（關閉戰鬥光效並簡化其他角色、怪物），並清理 Doll/Monster/Effect/Pet 的未引用快取。
- `AfkVisualCache` 逐一釋放靜態地圖 Sprite2D / TextureRect / Polygon2D / NinePatchRect 的 **可透過 res:// 路徑安全還原**貼圖，紀錄的只有資源路徑與 Node WeakRef，不保留資源強引用。
- **不**卸載 CollisionObject2D 子樹、`Entities`、CharacterBody2D、TileMapLayer、AnimatedSprite2D 和已掛腳本的地圖節點。這些可能影響移動、打怪、拾取、動畫訊號與座標。
- 返回時每批最多重新載入 24 張貼圖，恢復玩家原本畫質與視覺簡化偏好，再恢復地圖顯示；必要時依最新 Server packets 繼續同步。
- 掛機中伺服器要求換圖：正常執行換圖與位置同步，新的地圖在完成重建後再次卸載靜態畫面，避免套用舊地圖的資源快照。
- 不保證所有地圖的 RAM/VRAM 會等比例下降：不可安全重建的子資源或被其他系統引用的貼圖會保留。實際改善應觀察 **[AFK_MODE]** 的數值與 Windows process RAM/GPU 工作集，不能只用 `released` 數量推估。

## 測試及限制

- CI 靜態契約：`python -m unittest tests/test_afk_mode_contract.py`。
- Godot 行為測試：`godot --headless --path client --script res://tests/afk_visual_cache_regression.gd`。驗證靜態資源確實可卸載還原、玩家與地面物件未被刪、隱藏場景依然執行物理回呼。
- 尚需 Windows 遊戲實測：開啟自動打怪與自動拾取，掛機前／中／後與掛機中換圖各跑一段時間，比對 Server 擊殺、物品數量與 [PHYSICS_CADENCE]、[AFK_MODE]。
- 由於目前地圖/遊戲邏輯並未完全拆成獨立的 Server-driven headless world model，**不採用直接刪除整張地圖或活體 Entity 的做法**；這類全面重構必須再建立相應的自動戰鬥、碰撞與拾取 E2E 測試，不能冒充已完成。

- 對於可由 `res://` 還原、且未連接遊戲事件的 AnimatedSprite2D 與舊版 AnimatedMapObject，亦可卸載 SpriteFrames 並於恢復時還原原動畫、frame、播放狀態。
- 貼圖重新載入失敗不會顯示殘缺世界：失敗資源留在 retry 清單，返回按鈕可再次嘗試；已消失的舊地圖視覺節點自動跳過。

## 滑鼠與音效修正（2026-11-08）

- 掛機模式繼續使用遊戲原本的自製游標。掛機時只保留 CursorSprite 的位置更新，固定顯示一般 UI 指標；不再計算世界 hover、戰鬥／技能／自動走路游標與 tooltip，因此保留一致外觀但成本極低。Windows 系統游標持續隱藏，返回遊戲後恢復完整游標狀態。
- 進入掛機會停止 BGM／SE 播放並阻止新的音效／換圖 BGM 解碼，且強制 Master bus 靜音；返回遊戲時恢復使用者原有靜音設定、重新播放目前地圖 BGM。失焦期間仍保持靜音，避免 Alt+Tab 導致掛機出聲。

## 記憶體卸載診斷：先驗證，不擴大移除範圍

- 原先的 `[AFK_MODE] memory_mb` 實際取自 `Performance.MEMORY_STATIC`，是 Godot 內部統計，**不是 Windows 工作集 RAM**。因此不能單獨用它判斷 10 開能省多少真實 RAM。
- 新增 `[AFK_MEMORY]`：掛機前、剛卸載、3 秒後與還原後記錄 Godot 靜態配置、貼圖配置、Video resource 記憶體、Resource/Node 實例數以及相對掛機前差值，包含 PID 供 Windows Process 計數器交叉比對。
- `AfkVisualCache` 掃描結果現在逐類區分：`visited_nodes`、`visual_candidates`、`released`、`retained_embedded`（嵌入場景 subresource）、`retained_generated`（無可還原路徑）、`retained_missing`、`excluded_scripted`、`excluded_collision`、`excluded_entities`。保留這些資源是為了不破壞移動、碰撞與自動戰鬥。
- `released_refs` 是釋放欄位引用的次數，**不等於資源已被 Godot GC／OS 回收的數量**。若 `released=0` 且 `retained_embedded` 很高，表示目前的 AFK 卸載策略幾乎無法觸及主要場景素材，需要另外分析該地圖原始的資源擁有權，不能亂刪。
- 建議 Windows 同時用 `client/tests/profile_multiclient_windows.ps1` 依 PID 比對前後 RAM／Private Bytes／GPU 專用記憶體；只有實際觀測才能確認 OS 工作集是否下降。

- 新增 `afk_cursor_audio_regression.gd`，檢查掛機時仍使用自製滑鼠、固定一般 UI 游標且返回後恢復完整游標狀態，並確認掛機時 SE/BGM 不再播放；在非 headless 視窗還會檢查實際 `Input.mouse_mode`。

## 失焦掛機 GPU 停止渲染（2026-11-08 更新）

- 過去 AFK 監控分支無論是否失焦，都把 `RenderingServer.render_loop_enabled` 設為 `true`，導致背景掛機仍持續向 GPU 提交畫面。
- 現在進入 AFK 後失焦會將 render loop 設為 `false`，連監控面板文字計時器也停止。視窗重新聚焦則立即恢復監控面板與最新狀態。
- `Engine.physics_ticks_per_second`、NetworkManager 的 `_physics_process`、自動移動、戰鬥、拾取及地圖切換一律維持；不要用 `SceneTree.paused` 或停止整個視窗程序來達成 GPU 節省。
- 背景的 `Engine.max_fps=20` 僅是排程上限，已關閉 render loop，不等於 GPU 每秒仍繪製 20 張畫面；保留 Godot 固定物理 tick。
- 2026-11-08 實機 Log 曾發現 AFK 失焦後 render loop 已關閉、但 `Engine.max_fps` 殘留在 60；現在 AFK 不論焦點狀態都強制維持 20 FPS，避免多開時主迴圈無意義地以 60 Hz 喚醒。
- 自動化：`godot --headless --path client --script res://tests/afk_focus_render_regression.gd`，驗證渲染開關、重聚焦恢復與失焦後固定物理 tick 持續。
- Windows 實機要再驗證 GPU 負載（按 PID 監控）及 Alt+Tab 後正常自動打怪、拾物與監控頁面重新更新。背景 GPU 使用率不保證降為 0%，因為顯示合成與其他程序也可能使用 GPU。

## 系統 Select / PopupMenu 游標圖層修正

- Godot 的 OptionButton 下拉選單是獨立 PopupMenu Window/Viewport。原先開啟時會隱藏主 Viewport 的自製游標，僅在 PopupMenu 內新增另一個 GameCursorOverlay；滑鼠移出 PopupMenu 邊界後，因此沒有任何 Viewport 顯示游標。
- 現在 PopupMenu 開啟時主 Viewport 的自製游標保持可見，同時 Popup Window 仍有自己的自製游標。滑鼠在主畫面與下拉選單之間移動時由各自 Viewport 接手，不再出現 Select 範圍外游標消失。
